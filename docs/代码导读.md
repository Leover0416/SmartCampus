# SmartCampus 代码导读

> 阅读顺序建议：本文档（全局地图）→ 带 `【导读】` 注释的核心类 → 其余文件按模块查阅。

## 一、项目是什么架构？

**单体应用**，不是微服务/分布式：

```
浏览器 (Vue3 :5173)
    │  HTTP /api/v1/* 、 WebSocket /ws
    ▼
Spring Boot (:8080)  —— 业务 + JWT 鉴权
    │
    ├── MySQL        用户、会话、工单、FAQ、配置…
    ├── Redis        会话上下文缓存
    ├── Milvus       向量检索 (RAG)
    ├── MinIO        文档/图片对象存储
    └── 通义千问 API  对话、Embedding、Rerank
```

## 三、后端每个文件说明

### 3.1 启动与配置

| 文件 | 作用 |
|------|------|
| `CampusApplication.java` | Spring Boot 入口，`@MapperScan` 扫描 Mapper |
| `config/SecurityConfig.java` | 放行登录/健康检查/SSE；其余需 JWT |
| `config/JwtFilter` 见 `common/JwtFilter.java` | 从 Header 或 query 解析 token |
| `config/WebSocketConfig.java` | STOMP 端点 `/ws`，工单实时推送 |
| `config/RedisConfig.java` | Redis 连接与序列化 |
| `config/MyBatisPlusConfig.java` | 分页等 MP 插件 |
| `config/MilvusConfig.java` | 启动时连接 Milvus、建 collection |
| `config/MinioConfig.java` | MinIO 客户端 Bean |

### 3.9 mapper / model

- **mapper/**：每个表一个接口，继承 `BaseMapper`，复杂 SQL 在 `DashboardMapper`。
- **model/entity/**：与 MySQL 表一一对应（`ChatMessage`、`HumanTicket`…）。
- **model/dto/**：请求体（`LoginRequest`…）。
- **model/vo/**：返回给前端的视图对象。

## 五、核心业务流程（必读）

### 5.1 学生发消息（SSE）

```
ChatView.sendMessage()
  → GET /api/v1/chat/stream?query=...&sessionId=...
  → ChatController.stream()
  → AgentOrchestrator.handleStream()   // 意图 + RAG/工具
  → persistMessages()                  // 写入 chat_messages
```

### 5.2 转人工

两种方式：

1. **按钮** `POST /chat/handoff` → `HumanHandoffService.requestHandoff(..., appendNoticeMessages=true)` → 写消息 + 建工单  
2. **对话工具** `HumanTicketTool` → `requestHandoff(..., false)` → 只建工单，依赖 `persistMessages` 写历史

### 5.3 老师回复

```
TicketsView.sendReply()
  → POST /api/v1/tickets/{id}/reply
  → HumanHandoffService.reply()  // role=teacher 写入 chat_messages
  → 需要 TEACHER/ADMIN 角色（@PreAuthorize）
```

### 5.4 老师看历史

```
GET /api/v1/tickets/{id}/messages
  → 按 ticket.sessionId 查 chat_messages 全表
```
